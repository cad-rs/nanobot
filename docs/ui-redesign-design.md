# nanobot-ui 重构设计稿（v0.1 草案）

> 状态：草案，待评审。依据是 [`ui-redesign-research.md`](ui-redesign-research.md)（下称"调研"）和现有 `crates/nanobot-ui` 的代码。
> 约定：标 **［已定］** 的是项目负责人确认过的；标 **［建议］** 的是本稿的提议；标 **［待定］** 的需要拍板，集中列在第 10 节。
> 本稿只定界面与交互的规格，不含实现代码。

## 1. 目标与不变量

**目标**：把 `nanobot-ui` 的界面推倒重做，让布局、元素和交互各有一套成文的规则，而不是逐处临时决定。

**不变量**（重构不改变这些）：

- 基于 gpui（gpui-fast）与 `gpui-component` 0.9，不引入别的 UI 框架。
- 壳对产品是泛型的：产品通过 `SessionView` / `WorkspaceView` 提供会话，通过 `ViewportSlot` 提供视口，通过 `PanelHost` 注册面板。壳里不出现任何领域词。
- 视口在 Windows 上是盖在 gpui 内容之上的原生 surface，只有 `deferred` 的浮层能盖住它（`crates/nanobot-gpu/src/present.rs`）。
- 界面文案走 `i18n`，中英双语。
- Zed 的 `agent_ui` / `ui` / `markdown` / `editor` 等 crate 是 GPL-3.0，只借规格，不拷代码、不引依赖。

## 2. 现状与问题

以下均来自现有代码，不是印象。

| 现状 | 位置 | 问题 |
|---|---|---|
| 侧栏宽度写死 240px，不能收起、不能拖宽 | `shell.rs` `SIDEBAR_W` | 窄窗口下挤占空间；与［已定］的"可收起"冲突 |
| 视口宽度写死 520px，会话工作区吃剩余空间 | `shell.rs` `VIEWPORT_W` | 对 CAD 产品主次颠倒：三维视图被固定成窄条 |
| 顶部 46px 页眉放产品名、项目·会话标题、状态徽标、撤销/重做、保存/载入/导入 | `header()` | 全局操作与会话级信息混在一行；没有侧栏开合与待处理提示的位置 |
| 会话工作区自上而下：计划面板（常驻）→ 计算进度 → 澄清条或决策条 → 对话流 → 输入框 | `ai_workspace()` | 计划面板永远占着顶部；审批条在对话流上方，离输入框最远 |
| 对话流是普通滚动容器里的一串 `div` | `conversation_stream()` | 没有虚拟化，长会话全量重绘；没有尾部跟随 |
| 每个块统一画成"类型标签 + 事件序号 + 文本"，工具块只多一个状态徽标 | 同上 | 读一个文件和执行一次修改长得一样；没有折叠、没有输出、没有 diff |
| `Block { kind, text, tool_state, selection_ref }`，文本是纯字符串 | `model.rs` | 没有 markdown、没有流式增量、工具调用没有参数与结果的结构 |
| `SessionStatus` 四态：Active / Running / AwaitingReview / Archived | `model.rs` | 缺"出错"与"完成但未读"；Active 是"正在看"而不是会话自身的状态 |
| 输入框是单个 `Input`，Enter 发送 | `with_composer()` | 没有排队、插话、停止、`@` 引用、斜杠命令、模式切换 |
| 全壳没有任何 action、key context 或键位绑定 | `grep` 无结果 | 所有操作只能用鼠标 |
| 图标用 emoji（如 `📍`） | `conversation_stream()` | 跨平台字形不一致，无法随主题着色 |

## 3. 整体布局

### 3.1 区域划分

四区骨架保留（调研结论：与行业收敛形态同构），但主次与内部结构重排。

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 标题栏（产品名 · 项目选择器 ················· 全局操作：撤销 重做 保存 … 账号）│
├───────────┬────────────────────────┬───────────────────────────┬─────────────┤
│           │ ⟨⟩ ●2  会话标题 ▾  ＋ ⋯ │                           │             │
│  会话侧栏 ├────────────────────────┤                           │  面板 dock  │
│           │                        │                           │  （右）     │
│  项目 A   │      对话流            │        产品视口           │             │
│   ● 会话1 │    （虚拟化列表）      │      （ViewportSlot）     │             │
│   ◐ 会话2 │                        │                           │             │
│  项目 B   ├────────────────────────┤                           │             │
│   ○ 会话3 │  活动栏（计划·审批·队列）│                           │             │
│           ├────────────────────────┤                           │             │
│           │  输入框                │                           │             │
│  ───────  │  模型 · 权限档 · 上下文 │                           │             │
│  账号     │                        │                           │             │
├───────────┴────────────────────────┴───────────────────────────┴─────────────┤
│ 面板 dock（底）                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **标题栏**：只放全局的东西。产品名、项目选择器、撤销/重做、文件操作、账号。会话级信息全部下放到会话工作区工具栏。
- **会话侧栏**：见第 4 节。
- **会话工作区**（下称"会话列"）：四层——工具栏、对话流、活动栏、输入框。见第 5–7 节。
- **产品视口**：`ViewportSlot::element`，壳不在其上叠加任何非 `deferred` 内容。
- **面板 dock**：左 / 右 / 上 / 下四区沿用 `PanelHost`，本次只改外观与开合，不改注册接口。

### 3.2 宽度分配

| 区域 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 会话侧栏 | 280px | 240–480px，且 ≤ 窗口宽 40% | 可拖宽；可隐藏［已定］ |
| 会话列 | 440px | 最小 360px | 可拖宽；对话内容最大行宽 760px，超出后居中 |
| 产品视口 | 吃剩余空间 | 最小 320px | 主区［已定］ |
| 右侧 dock | 300px | 240–560px | 可拖宽；可收起 |

宽度与开合状态持久化到用户设置（`ui.layout.*`），按产品而不是按项目存。

### 3.3 窄窗口断点

断点写成常量，逐级折叠。自动折叠不改写用户手动保存的偏好，窗口恢复宽度后回到原状。

| 级别 | 触发（窗口宽） | 动作 |
|---|---|---|
| 0 | ≥ 1280px | 四区全显 |
| 1 | < 1280px | 会话侧栏自动隐藏 |
| 2 | < 1040px | 右侧 dock 收起为可唤出的抽屉 |
| 3 | < 760px | 会话列与视口不再并排，二选一切换；视口模式下保留一条可唤出的最小输入条 |

高度 < 560px 时，活动栏折叠成单行摘要。以上像素值是起点，调研没有可直接套用的来源（被调研的断点多以终端列为单位），需在真实窗口上调。

### 3.4 浮层规则

由视口是原生 surface 这一约束推出，没有先例可循：

1. 会话列发起的弹层（`@` 补全、斜杠菜单、模型与权限选择器、审批范围下拉）向会话列内部展开：向上弹出、左对齐输入框、宽度不超过会话列。
2. 任何可能越过视口边界的弹层一律走 `deferred`。壳提供统一封装，业务代码不直接创建非 `deferred` 浮层。
3. 全局模态（设置、命令面板、会话历史）走 `deferred` 居中，带遮罩并拦截鼠标。
4. 应用内提示不落在视口上方，放在会话列顶部或标题栏下方。
5. 拖动分隔条时，视口 surface 的重排是否闪烁未知，列入开工前验收（第 9 节）。

## 4. 会话侧栏

### 4.1 结构

```
┌───────────────────────────┐
│ [过滤会话…]           ＋  │  过滤框 + 新建会话
├───────────────────────────┤
│ ▾ 项目 A            ● 1   │  项目标题：折叠箭头 · 名称 · 待处理汇总
│     ◐ 支架开孔方案    3m  │  会话行
│     ● 等待确认：倒角  12m │
│     ○ 法兰初稿        2h  │
│ ▸ 项目 B                  │  已折叠的项目
│ ▸ 较早（14）              │  不活跃分组，默认折叠
├───────────────────────────┤
│ (A) Ada · Pro             │  账号
└───────────────────────────┘
```

- **分组**：默认按项目分组；产品可通过现有的 `SidebarProjection` 换成自己的分组（比如按设计对象）。投影没提到的会话仍落在尾部分组里，这条现有契约不变。
- **项目标题**：可折叠［建议］。折叠时仍显示待处理汇总，否则折起来就看不到"有会话在等你"。
- **不活跃分组**：超过 72 小时没有活动的会话收进"较早"，默认折叠（Amp 的做法）。归档的会话不在主列表，进历史视图。
- **排序**：组内按"等待确认 → 运行中 → 其余按最近活动时间"。

### 4.2 会话行

一行包含：状态徽标、标题（单行截断）、相对时间；悬停时右侧出现归档按钮。第二行可选，显示分叉来源（`BranchMarker`）或计划进度（`3/7`）。

状态五态，取代现有的四态：

| 状态 | 徽标 | 含义 | 优先级 |
|---|---|---|---|
| 等待确认 | 警示色实心点 | 有审批、澄清或待裁决的计划 | 最高 |
| 出错 | 错误色实心点 | 上一回合以错误结束 | 高 |
| 运行中 | 旋转指示 | 回合进行中 | 中 |
| 完成未读 | 强调色实心点 | 回合已结束，用户还没看过 | 中 |
| 空闲 | 无徽标 | 已读，或从未运行 | 低 |

"正在查看"不是状态，而是行的选中样式（底色加左侧强调条）。归档是独立的布尔属性。

### 4.3 交互

- 单击行：切换到该会话，并把"完成未读"清为"空闲"。
- 键盘选中项与当前打开的会话是两个独立状态：方向键浏览不打断正在看的对话，`Enter` 才切换（Zed 的做法）。
- 行内重命名：`F2` 或双击标题。
- 过滤框：按标题子串过滤，匹配不到时显示空状态。
- 右键菜单：重命名、分叉、归档、删除。删除需确认。

### 4.4 收起 ［已定］

- 侧栏收起后**完全隐藏**，不留图标栏。
- 开合按钮和"N 个等待处理"徽标放在**会话列工具栏**最左侧，侧栏隐藏时入口仍在。
- 徽标计数 = 等待确认 + 出错 的会话数（不含当前正在看的会话）；为 0 时不显示。点击徽标：展开侧栏并把键盘选中项移到第一个待处理会话。
- 快捷键见第 8 节。

## 5. 会话列：工具栏与对话流

### 5.1 工具栏

```
│ ⟨⟩  ●2 │ 支架开孔方案 ▾                          ＋   ⋯ │
  │    │     │                                    │    └ 选项菜单
  │    │     └ 会话标题（单击就地编辑；▾ 打开最近会话切换器）
  │    └ 待处理徽标
  └ 侧栏开合
```

选项菜单：重新生成标题、导出为 Markdown、分叉会话、归档、打开会话历史。高度 36px。

### 5.2 对话流

虚拟化的变高列表，新内容到达时跟随尾部；用户向上滚动即暂停跟随，出现"回到底部"按钮。

条目类型与外观：

| 条目 | 外观 |
|---|---|
| 用户消息 | 带 1px 边框的小卡片，底色比面板略亮，等宽字体；单击进入编辑态（见 7.4） |
| 助手消息 | 无框 markdown，UI 字体；代码块带复制按钮；流式到达时按固定节拍匀速揭示 |
| 思考 | 一行"图标 + 思考 + 用时"，默认折叠；展开后左侧竖线缩进，限高可滚动 |
| 工具调用（行内） | 一行"种类图标 + 标签"，可点开看参数与结果 |
| 工具调用（卡片） | 带头部的卡片：种类图标、标题、状态；正文是 diff / 输出 / 参数 |
| 计划 | 卡片：步骤清单，每步一个三态标记；与活动栏中的计划摘要同源 |
| 检查结果 | 一行"通过 / 未通过 + 名称"，未通过时可展开详情 |
| 回合结束 | 一行弱化文字：用时、改动摘要 |
| 错误 | 提示条：分类标题 + 说明 + 重试按钮 |

**密度规则**（本次重构最重要的一条视觉规则，来自 Zed 与 opencode）：

> 工具调用只有在**需要确认**、**会修改产品状态**、或**有持续输出**时才画成卡片；其余一律是一行标签。

连续多个行内调用合并成一行摘要（"读取了 3 个对象，查询 2 次"），点开再展开（Cline 的做法）。

卡片状态：等待确认（警示色边框）、运行中（旋转图标）、完成（无额外标记）、失败 / 取消 / 被拒（虚线边框，不只靠颜色）。输出默认只显示末尾 5 行，带"还有 N 行"的展开入口。

**空间锚点**：现有的 `selection_ref` 保留，画成可点击的 chip，点击后在视口中高亮对应对象。图标换成矢量图标，不再用 emoji。

## 6. 会话列：活动栏

活动栏贴在输入框上方，把现在分散的"计划面板、计算进度、澄清条、决策条"收在一处，并加入消息队列。没有内容的分区不出现；整栏为空时不占高度。

```
├──────────────────────────────────────────────┤
│ ▸ 计划  3/7 · 执行中：生成倒角            ▓▓▓░ │  计划摘要（可展开为步骤清单）
├──────────────────────────────────────────────┤
│ ! 应用修改：在 Body1 上添加 4 个 M6 通孔      │  待审批
│   [允许一次]  [始终允许 ▾]  [拒绝]           │
├──────────────────────────────────────────────┤
│ ▸ 已排队 2 条                                │  消息队列
└──────────────────────────────────────────────┘
```

| 分区 | 出现条件 | 内容 |
|---|---|---|
| 计划 | `plan_phase != None` | 摘要行：完成数/总数、当前步骤、阶段；展开为步骤清单。计算进度（`progress()`）作为摘要行右侧的进度条 |
| 待裁决计划 | `Contingent` | 现有的 接受 / 拒绝 / 修改，以及 `settlement_items` 的逐项取舍 |
| 澄清 | `Clarify` | 问题列表；回答写在输入框里发送 |
| 待审批 | 有工具调用等待确认 | 动作描述 + 三个按钮（见 7.2）。限高可滚动，避免把对话流挤出视野 |
| 队列 | 有排队消息 | 折叠时显示条数；展开后每条可编辑、移除、改为立即发送 |

待审批同时出现在两处：对话流里对应的卡片边框变警示色，活动栏出现操作按钮。前者说明"批的是哪一步"，后者保证不用滚动就能操作。

## 7. 输入与交互

### 7.1 输入框

```
┌──────────────────────────────────────────────┐
│ 描述你要做的修改…                            │
│                                              │
│ ＋ @                                      ➤ │
├──────────────────────────────────────────────┤
│ 模型 ▾ · 逐项询问 ▾ · 上下文 42%              │
└──────────────────────────────────────────────┘
```

- 多行，随内容增高到上限后内部滚动；可展开为大输入框。
- `@` 引用产品对象或文件，插入为不可分割的 chip；`/` 打开命令补全。两者的候选由产品提供，壳只管呈现。
- 发送按钮三态：空闲时"发送"；忙且有输入时"排队"；忙且无输入时"停止"。
- 底部状态行：模型、权限档位、上下文用量（70% 变警示色，90% 变错误色）。
- 可打印字符永远进入输入框；全局快捷键全部带修饰键。

### 7.2 审批

三个选项加一个下拉：

- **允许一次**
- **始终允许**（下拉选范围：本会话 / 此类操作）。选定后先展示规则实际覆盖的范围，再确认。
- **拒绝**。拒绝后就地展开反馈输入，`Enter` 提交、`Esc` 取消。

审批等待期间直接在输入框打字发送，等同于"拒绝并附反馈"。主按钮文案随动作类型变化（"应用修改""执行脚本"等），由产品提供动词，壳提供默认值。

**权限档位**常显在输入框下方，`Shift+Tab` 循环切换，变更在对话流里留一行痕迹：

| 档位 | 行为 |
|---|---|
| 逐项询问 | 每个会修改产品状态的动作都确认（默认） |
| 自动接受低风险 | 只读与可撤销的动作自动通过 |
| 只规划 | 只产出计划，不执行 |
| 完全放行 | 不询问；档位标识用警示色 |

档位怎样映射到 `nanobot-tools` 的 `ApprovalPolicy` 由内核决定，壳只负责显示与切换。

### 7.3 排队与插话

- 忙时 `Enter` = **排队**，回合结束后按序发送。
- `Ctrl+Shift+Enter` = **立即发送**（插话）：在下一个工具调用边界送达。
- 数据模型里把两种投递语义分开（`queue` / `steer`）。
- **处理排队消息不得隐式批准任何待决审批**（Roo 的反例）。
- `Esc`（无弹层、非编辑态时）= 停止当前回合。

### 7.4 回退

以用户消息为粒度。单击已发送的用户消息进入编辑态，其后内容盖一层半透明遮罩；确认时选择：

1. 只回退对话
2. 回退对话并恢复产品状态
3. 分叉为新会话（原会话不动）

回退后保留一条"可重做"的横幅，直到发出新消息。界面必须如实标出哪些改动不在恢复范围内。**"恢复产品状态"依赖产品能给出检查点**，调研里所有先例都建在 git 上，CAD 文档怎么做没有先例［待定 D4］。

## 8. 键位

当前壳没有任何键位，全部新建。原则：与 Zed 的 Windows 键位和跨工具通行约定对齐；所有键位可配置；按钮的 tooltip 上显示对应键位。

| 动作 | 默认键位 | 作用域 |
|---|---|---|
| 发送 / 忙时排队 | `Enter` | 输入框 |
| 换行 | `Shift+Enter` | 输入框 |
| 立即发送（插话） | `Ctrl+Shift+Enter` | 输入框 |
| 停止回合 | `Esc` | 会话列 |
| 切换权限档位 | `Shift+Tab` | 会话列 |

## 9. 视觉规范

**颜色角色**（映射到 `gpui-component` 主题，不新增调色板）：

- 表面三层：面板底；抬升（卡片、输入框）；卡片头部的微弱叠色。
- 边框一种，配两档透明度；聚焦边框另设。
- 文本两级：主文本、弱化文本。
- 语义色五种：强调（进行中、选中）、成功、警告（等待确认）、错误、弱化（取消）。

**字体**：UI 字体用于助手正文与控件；等宽字体用于用户消息、命令、路径、代码、输出。字号四级：14（正文）/ 13（标签、工具名）/ 12（用户消息、输出）/ 10（角标）。会话列支持独立字号缩放。

**间距**：4px 基准。用户消息卡片内边距 12×8；助手消息左右 20、块间距 12；缩进内容用左侧 1px 竖线加 16px 内缩；圆角统一 6px。

**图标**：矢量图标，按工具**种类**而不是工具名映射（读取、编辑、删除、移动、搜索、执行、思考、抓取、其他，外加产品自定义的类别）。不使用 emoji，不取用 Zed 的图标资源。

**动效**只有四种，各有语义：生成中的点状指示；等待确认的另一种指示；占位内容的 shimmer；运行中工具的旋转图标。提供"减少动效"开关。

## 12. 实施顺序

开工前先做四项最小验收，任何一项不通过都会改变后面的方案：

1. `gpui` 的变高 `list` 在 gpui-fast 当前版本里的尾部跟随与局部更新能力。
2. `gpui-component` 的 markdown 文本视图在持续流式追加下的帧耗时与文本选择。
3. 输入框里能否实现不可分割的内联 chip 加补全弹层。
4. 视口 surface 旁拖动分隔条的表现，以及 `deferred` 浮层盖住视口的效果。

然后分阶段，每阶段结束时壳都可运行：

| 阶段 | 内容 | 验证 |
|---|---|---|
| 1 | 布局骨架：可拖宽分区、侧栏开合、断点、布局持久化、标题栏与会话列工具栏 | 单元测试覆盖断点与持久化；手动验证拖动 |

| 4 | 活动栏与输入框：计划、审批、澄清、队列、发送三态、权限档位 | 审批与排队的状态流转测试 |
| 5 | 键位、命令面板、回退、空状态与错误态 | 键位表逐项验证 |
